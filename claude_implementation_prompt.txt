5. PROCESSOR AND SYSTEM

Create new SystemVerilog RTL for a multicycle RV32IM core: little-endian, 32 registers of 32 bits, x0 always zero, and a 32-bit PC. Implement the base integer instructions and all eight M-extension instructions according to the official specification. Consult https://docs.riscv.org/reference/isa/ for semantics and corner cases. Do not claim full architectural conformance without adequate evidence.

Include byte, halfword, and word loads/stores, correct sign extension, jumps, signed/unsigned branches, and 32-bit effective addresses. Instructions are four-byte aligned. Misaligned halfword/word accesses, illegal instructions, out-of-range memory accesses, and ECALL/EBREAK must cause an observable error halt with PC and instruction. FENCE may complete without additional effects in this simple sequential environment. Document this execution-environment policy; do not silently treat unknown instructions as NOPs.

C/A/F/D extensions, interrupts, MMU, and an operating system are outside scope. Do not rely on CSRs for cycle counting. Implement the complete M extension, not only MUL. Test MULH/MULHSU/MULHU, signed/unsigned division and remainder, division by zero, and signed overflow according to the ISA. Datapath RTL must be synthesizable; identify simulation memory models and testbench code separately.

Unified program/data memory: 1 MiB at 0x00000000..0x000FFFFF. Reset PC = 0x00000000, containing startup code. Initial stack pointer = 0x00100000, 16-byte aligned and growing downward. The linker must verify that code, constants, model, input tensors, bss, any reserved heap, and stack fit without overlap. Reserve an explicit 64 KiB stack region. If the system does not fit, report actual sizes and the blocker instead of silently increasing memory.

Use an explicit memory request/response interface and wait for the response before retiring an instruction. Document signals and transactions. The testbench serves RAM with a documented fixed latency; processor tests must also exercise additional wait states. Do not make execution depend on an instantaneous response.

MMIO is outside RAM, using aligned 32-bit writes:
0x10000000: TX, low byte used for diagnostic characters.
0x10000004: CASE_ID, index of the input being processed.
0x10000008: SCORE_0, sign-extended int8 output as a 32-bit value.
0x1000000C: SCORE_1, same representation.
0x10000010: SCORE_2, same representation.
0x10000014: SCORE_3, same representation.
0x10000018: PREDICTED_CLASS, 0..3, indicating all scores for that case are ready.
0x1000001C: MEASURE, write 1 immediately before Invoke() and 2 immediately after it; the testbench measures cycles between these events.
0x10000020: STATUS, write 1 after all cases finish without execution errors, or 2 on a firmware/TFLM error.

Capture these writes from actual processor transactions, validate their order, and export results. STATUS=1 means execution finished; the external checker decides whether the outputs are correct. Document the precise cycle-counting convention and measurement overhead. Report allocation/setup separately from Invoke() timing.
